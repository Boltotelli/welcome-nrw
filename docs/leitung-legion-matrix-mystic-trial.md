# Legion matrix and Mystic Trial · 2026-10-30

SL/Tri player planning uses a table with mutually exclusive L1/L2 checkboxes. Bear planning uses one checkbox per configured trap (BT1/BT2). Checking a different column stages a move; unchecking the current column stages removal. Availability, notes and roles are staged too. A single "Save all changes" button saves all changed players, including filtered-out rows. Individual row save buttons have been removed. The toolbar displays the number of pending players and offers discard. Drafts stay in memory across filtering, data refresh and event/date changes; each event/date has its own save scope. Leaving/reloading the document warns about pending drafts; drafts do not survive a reload. Sequential saves use existing permission checks and assignment endpoints. Successful rows are removed from the pending set; a failure stops the run and retains the remaining edits for retry. No atomic backend batch operation is implied. Tables open by default and support keyboard input and horizontal scrolling on narrow screens.

FightClub displays, sorts and balances by the provider's `ranks.mystic_trial`, rather than general power. The player dossier displays the same score and retrieval time. Missing scores are unknown and excluded from new automatic placements. Bear planning retains general power. Source: https://api.mightpulse.com/ (Player / ranks).

The manual roster refresh requests `include=base,ranks` for authorized listed IDs, including external accounts. Each batch contains at most three concurrent player requests. Scores have a one-hour cache, matching provider freshness; rate limiting stops the run. General roster refreshes preserve existing scores. No automatic score backfill or scheduled provider requests are added.

The additive Supabase migration `member_mystic_trial_scores` adds nullable `mystic_trial bigint` and `mystic_trial_fetched_at timestamptz` columns to `aos_member_power_snapshot` and `aos_member_power_history`. Scores are constrained to 0…9999999999999. Existing RLS and authorization remain unchanged. API version 65 supplies these fields.

Automatic Swordland placements exclude Mercenary, Swordshrine, Reformation and all four Undercellars positions. "Keep existing" retains open objectives; existing positions at closed starting objectives are replanned in the preview. If availability or missing score prevents replanning, the preview explicitly names players still at closed objectives. Applying the preview is required to save changes; no live orders are moved automatically. Manual placement remains available for later battle phases. TriAlliance still requires an explicitly selected starting side. Team messages include the supplied English North/South/Guerilla duties beneath player names; individual game-label copies remain compact.

A collapsible "Without a map position" panel appears below Assign / move. It lists available players in the selected legion with no valid map objective, scoped to the current event/date. Selecting a name fills the assignment selector without saving. Assigning or removing a player updates this list.
