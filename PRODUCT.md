# AllianceOS · Welcome NRW

Alliance leadership operations for the Kingshot alliance NRW in kingdom 1044.
R4 and R5 staff use it repeatedly to assign players to bear slots and Swordland
teams, coordinate attendance, manage members and linked accounts, plan transfers,
publish laws, schedule events and configure Discord event messages and permissions.

## Surface and success

The leadership console is an Operate surface. Success is quick, reliable planning
with verified existing data, visible pending responses, searchable dense lists and
predictable forms. Desktop supports sustained administration; phone supports quick
checks and assignments. German, English, French and Spanish remain available.

## Brand commitments

Product name AllianceOS; alliance NRW; kingdom 1044; existing NRW crest; restrained
NRW gold. Professional, precise, calm and recognisable, with no gaming effects,
generic hero slogans, gradient cards or invented metrics. Both themes are required.

## Non-negotiable boundaries

Only https://boltotelli.github.io/welcome-nrw/leitung/ receives the redesign.
The Vercel production domain and deployment commit must remain unchanged.
No authentication, Supabase, database, Edge Function, API or Vercel configuration
changes. Keep every existing module, permission, save, delete, copy, filter,
translation and URL navigation function. Never publish test fixtures as live data.
Keep the Bear optimizer, Welcome and other GitHub Pages routes working.

## Implementation truth

Existing static HTML, CSS and vanilla ES modules under leitung/.
The pages-atelier CSS and JS are only loaded for the exact GitHub Pages hostname.
App logic and module renderers remain authoritative. Existing GitHub Pages pipeline
combines the stable Bear source with current leadership/dashboard/Welcome sources.

## Delivery authority

The supplied brief authorizes three distinct concepts, an explained recommendation,
implementation of the best direction, Playwright QA and GitHub-Pages-only release.
No extra concept-selection pause is needed. Authenticated UI tests use the user's
existing browser session. Live destructive or data-changing tests are not needed.
